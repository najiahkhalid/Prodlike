# Security review

- **Reviewed:** 2026-11-22 (Phase 6B) · **Scope:** the local laptop demo and the classroom pilot (ADR-001). Prodlike is
  not deployed to the internet; see "Known limitations".

Every control below names the automated test that proves it, so this page stays true as the code changes.

## Threats and controls

| Asset / threat                                           | Control                                                                                                                                                                                                                                                                                                                    | Evidence                                                                                                                                  |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Host machine**: learner code escapes its sandbox       | One container per attempt: non-root `node` user, no network, read-only root filesystem, all Linux capabilities dropped, `no-new-privileges`, 512 MB, 1 CPU, 128 processes (ADR-005)                                                                                                                                        | `sandbox.int.spec` "runs the container locked down (NFR-10)"; CI `check-scenarios.mjs` (non-root, no network) for every scenario image    |
| Host: learner runs arbitrary shell commands              | No shell. Each terminal line is parsed and checked against the scenario's allowlist, then run with `docker exec` and a 30 s kill timeout                                                                                                                                                                                   | `policies.spec` (quoting, allowlist); `sandbox.int.spec` "runs allowlisted commands and refuses everything else (FR-06)"                  |
| Host: file access outside the workspace                  | Paths are normalised and must stay inside `/workspace`; read-only files cannot be written                                                                                                                                                                                                                                  | `sandbox.int.spec` "refuses paths outside the workspace", "refuses to write read-only files"                                              |
| Hidden tests leak before scoring                         | Hidden tests are copied into the sandbox only when the attempt finishes; briefs never contain faults, hidden tests or hints                                                                                                                                                                                                | `access.int.spec` "serves a brief with no hidden data"; `phase1.spec` (brief does not mention the incident)                               |
| **Accounts**: password theft                             | bcrypt (12 rounds); minimum 10 characters; a dummy hash equalises login timing for unknown emails                                                                                                                                                                                                                          | `auth.int.spec` "never returns the hash", "rejects a wrong password without saying which part was wrong"                                  |
| Session theft                                            | 15-minute access JWT and a rotating refresh token, both `HttpOnly`, `SameSite=Lax`, `Secure` behind HTTPS. Replaying an old refresh token revokes every session                                                                                                                                                            | `auth.int.spec` "rotates refresh tokens and revokes every session when an old one is replayed"; `security.int.spec` cookie flags          |
| Account takeover after a leak                            | Password reset uses one-time, 30-minute links; resetting or changing the password signs out every other session                                                                                                                                                                                                            | `auth.int.spec` "resets a forgotten password…", "changes the password: needs the current one, signs out other sessions…"                  |
| Brute force and sign-up spam                             | Rate limit on every credential endpoint (`AUTH_RATE_LIMIT`, default 10/min/IP) and a global limit of 300 requests/min/IP                                                                                                                                                                                                   | `rate-limit.int.spec` "returns 429 RATE_LIMITED after too many login attempts"                                                            |
| **Authorisation**: learner reaches instructor/admin data | Global auth guard; `@Roles` on every instructor and admin route; web middleware redirects too                                                                                                                                                                                                                              | `access.int.spec` anonymous 401 / learner 403; `phase1.spec` "a learner cannot reach the instructor area"                                 |
| One instructor reads another's class (NFR-13)            | Every cohort, assignment and drill-down query checks ownership and answers **404, not 403**, so ids reveal nothing                                                                                                                                                                                                         | `instructor.int.spec` isolation tests; `phase5.spec` "another instructor cannot see this class"                                           |
| One learner opens another's attempt                      | Attempts are looked up by owner; others get 404                                                                                                                                                                                                                                                                            | `sandbox.int.spec` "hides attempts from other users"; `phase2.spec` "workspace pages are private"                                         |
| **Input**: malformed or hostile input                    | Every body and query is validated by a shared zod schema (`ZodPipe`); errors use one shape `{code, message, action, fields}` without stack traces                                                                                                                                                                          | `auth.int.spec` validation tests; `security.int.spec` "malformed JSON … no stack trace"                                                   |
| CSV export runs formulas in Excel (CSV injection)        | Cells starting with `= + - @` are prefixed with `'`                                                                                                                                                                                                                                                                        | `instructor.int.spec` CSV test                                                                                                            |
| **Browser**: XSS, clickjacking, sniffing                 | React escapes output; Content-Security-Policy (`default-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`; HSTS behind Caddy; no `Server` / `X-Powered-By` banners | CI `stack` job "Security headers on web and API responses"; `security.int.spec`; `quality.spec` fails on any CSP violation in the browser |
| **Secrets** in the repository                            | `.env` files are git-ignored; the API refuses to start without a JWT secret of at least 16 characters; the demo admin password must be changed in `.env`                                                                                                                                                                   | `config/env.ts` validation                                                                                                                |
| **Dependencies** with known vulnerabilities              | `pnpm audit --prod --audit-level high` runs in CI; patched versions are pinned or overridden in `package.json`                                                                                                                                                                                                             | CI step "Dependency audit"                                                                                                                |

## Dependency audit (2026-11-22)

- **Before:** 68 advisories in production dependencies (5 critical, 28 high), mostly in Next.js 15.1, Express middleware
  pulled in by NestJS, `tar-fs` (via dockerode) and `lodash`.
- **Fixed by upgrading:** Next.js 15.1.6 → 15.5.28, NestJS 10.4.15 → 10.4.22, dockerode 4.0.2 → 4.0.10,
  Playwright 1.49 → 1.58. **Fixed by overrides** (same major version): `lodash` 4.18.1, `multer` 2.5.0, `body-parser`
  1.20.9, `path-to-regexp` 0.1.13, `postcss` 8.5.18.
- **After:** 0 critical, 0 high, 13 moderate, 2 low; plus **one accepted high**:
  - `GHSA-mrhx-c7xc-m3w5`: zod 3 can use a lot of memory validating a huge constrained collection. The fix is zod 4,
    a breaking major upgrade of the schema layer shared by the web app and the API. It is not reachable here:
    Express rejects request bodies over 100 kB (its default, which Prodlike does not raise) before zod runs, and
    the only collection in a request schema (the Scenario Builder's rubric weights, instructors only) is
    therefore small.
    Recorded in `package.json` (`pnpm.auditConfig.ignoreGhsas`) so the CI audit stays strict for everything else.
    Revisit when moving to zod 4.

## Known limitations

- **The API can control Docker.** It needs the Docker socket to start sandboxes, which is equivalent to root on the
  host. That is acceptable for a laptop demo with trusted operators, but Prodlike must not be exposed to the
  internet as it is. A real deployment would run sandboxes through a separate, minimal runner service (or rootless
  Docker / gVisor) on its own machine.
- **CSP allows inline scripts.** Next.js inlines its hydration data without nonces; moving to nonce-based CSP needs
  dynamic rendering of every page. React's escaping remains the main XSS defence.
- **Rate limits are per IP.** In a lab behind one NAT, every learner shares the limit; raise `AUTH_RATE_LIMIT` for a
  class (see `docs/DEMO.md`, Phase 6C).
- **No email delivery.** Password-reset links go to the API log in this build (`MailService`); a real SMTP provider
  is needed outside the demo.
